在本單元中，我們將學習如何將專業的公文排版美學、作業批改原則封裝為專屬技能書 (Custom Skill)，讓 AI 特務永久學會您的客製化行政工作流！

行政痛點

AI 生成的排版風格總是混亂不符公文規範？

每次叫 AI 產生 Word 或教材，標題字體大小、顏色都不一樣？每次都要重複下一大堆排版提示詞，既繁瑣又容易遺漏？

傳統做法
每次對話都得重新貼上：「大標要藍色、中文字型要標楷體、首行要縮排...」AI 聊到一半還會忘記。
技能包解法
將排版規範封裝在目錄下，呼叫 @doc_expert，AI 自動讀取手冊、寫代碼生成完美格式。

運作原理

技能包如何教導本地端 AI 大腦？

Custom Skill 是將專家規則封裝成靜態 Markdown 文件，AI 偵測到召喚後，在背景進行學習並注入代碼。

1. 定位與偵測
偵測對話中出現的標記 @doc_expert，在 .agents/skills/ 下找到 SKILL.md 檔案。
↓
2. 學習與注入
AI 自動調用 view_file 讀取手冊，並在背景寫 Python code 時將排版規範寫入程式中。

Anthropic 官方解密

一個 Agent Skill 其實有哪「三層」？

多數人只寫到第二層（指令 SOP），卻漏掉了真正的槓桿——第三層「工具與確定性腳本」！

1. 描述
何時該叫出它：SOP 封面適用情境，讓 AI 自動判斷何時動態觸發。
2. 指令
步驟怎麼做：SOP 內文操作規範，多數人止步於此。
3. 工具與腳本 🌟
附範本與確定性 Code：能用代碼確定解決的，就別讓 AI 每次重新猜測！

Anthropic 避坑指南

萬能 Skill 是個陷阱！拆成能組合的小 Skill

工程師都把 Skill 拆成獨立的小模組。各司其職、互相串接，才不會「改一個，壞一片」！

❌ 萬能包 (Monolithic)

全包在同一個 SOP

抓資料 + 清洗 + 畫圖全塞在一起。手冊長度爆表、耗 Token，且維護困難（改 A 壞 B）。

✔️ 模組化 (Composable) 🌟

拆成可組合小模組

拆成 抓資料 / 清洗 / 畫圖表。各司其職，還能彈性互相 Call 串接（例如：@pdf + @docx）。

概念比較

Gemini / Gems / GPTs vs. Agent Skill

Gems / GPTs 是「雲端聊天室換面具」；Agent Skill 是「給本機 AI 特助可執行的 SOP 與工具箱」！

比較維度 一般 Gemini / ChatGPT Google Gems / Custom GPTs Custom Skill (技能包) 🌟
形象定位 臨時聊天員 雲端客服角色面具 本機特助 SOP + 工具箱
記憶載入 一次對話易遺忘 常駐硬讀，易稀釋專注度 按需動態載入，0 佔用注意力
本機動手 ❌ 純文字回應 ❌ 無法存取本機硬碟 100% 本機自動化執行 Code
組合與可攜 ❌ 無法組合 ❌ 綁定特定雲端平台 可組合鏈式 Call，跨平台可攜

觀念解惑

沒有裝 PDF Skill 就無法讀取檔案了嗎？

答案是：「沒裝也能讀基礎純文字，但裝了才能擁有 99 分的專家級精準度與穩定性！」

⚠️ 沒裝 Skill (基礎 60 分)

AI 靠基礎程式裸讀

• 只能讀簡單純文字。
• 遇到複雜表格、雙欄排版或圖表會變亂碼。
• AI 每次都要花 Token 重新試錯猜程式碼。

🌟 有裝 Skill (專家 99 分)

AI 遵照專家 SOP 操作

• Skill 是 SOP 專家指南，而非行為開關。
• 對照 Anthropic 最佳實踐，表格對齊、文字順序 100% 精準！
• 省時省 Token，品質永久穩定。

使用限制

必須掌握的安全防線與限制

技能包不是萬能魔法，在使用時有其特定的限制與安全檢查機制：

1. 讀檔工具依賴：AI 必須擁有讀取檔案工具（view_file）方可生效。

2. Token 預算限制：技能手冊不宜像整本書那樣長，會消耗大量 Token 並降低 AI 的專注度。

3. 靜態指令防禦：技能包本質是規則，無法讓 AI 跨越權限去做它本來就做不到的事情。
