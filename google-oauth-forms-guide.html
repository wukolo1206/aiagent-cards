先記住這個安全邊界

本手冊只帶你完成設定與測試，不會替你執行 OAuth，也不會上傳任何資料。所有程式片段使用範例名稱與必要 scopes；實際操作時，請只在自己的專案資料夾保管檔案。

01先搞懂授權

外掛、MCP 與 API 的差別

你要做什麼

先把三個常被混在一起的名詞拆開：外掛是產品功能，MCP 是工具連接方式，API 則是服務提供的程式介面。本手冊要做的是讓本機程式透過 Google API 工作。

操作清單

  • 把 API 想成「服務可以接受的指令入口」。
  • 把 OAuth 想成「使用者授權某個程式代表自己做事」。
  • 把本機 Python 程式當成這次的呼叫者，不把權限交給不明網站。

教師口訣

API 做事，OAuth 認人，MCP 接工具。

成功判斷

你能說出這次流程不是「把帳號密碼交給程式」，而是由 Google 顯示授權畫面，讓你決定是否允許特定 scopes。

02先搞懂授權

credentials.json 與 token.json 的角色

你要做什麼

把「程式是誰」與「使用者已授權什麼」分開理解。credentials.json 是用戶端設定；token.json 是完成授權後可重用的權杖檔案，兩者都要視為敏感檔案。

credentials.json

Google Cloud 下載的用戶端設定，描述應用程式如何發起登入流程；它不是老師的帳號密碼。

token.json

完成同意後由本機流程保存的可重用授權結果。不要貼到聊天、教材或版本控制。

注意事項

只把 credentials.json 放進自己的專案資料夾，並將兩個 JSON 排除在公開分享之外；本手冊不會要求你貼出內容。

成功判斷

你能用一句話分辨：credentials.json 說明「程式是誰」，token.json 記錄「使用者授權後能重用的結果」。

04Google Cloud 專案

沒有空間時，重複使用舊專案

你要做什麼

如果建立新專案時遇到配額或空間限制，不必反覆點擊建立。先找一個你有權限管理、用途相近的舊專案，再確認它沒有放著不認得的測試設定。

  • 確認專案名稱與用途，避免誤選同事或其他課程的專案。
  • 確認你是該專案的管理者或具備啟用 API、設定 OAuth 的權限。
  • 若舊專案已有不熟悉的 OAuth 用戶端，先記錄現況再新增，不要刪除別人的設定。

錯誤排除｜專案選錯

若後續找不到 API 或品牌資料，先回到專案選擇器檢查目前專案；許多「按鈕不存在」其實是工作範圍選錯。

成功判斷

你已選定一個可管理、用途清楚的 Cloud 專案，並且能在每個後續頁面辨認目前專案名稱。

05Google Cloud 專案

啟用 Google Forms API

你要做什麼

在目前專案中打開 API Library，搜尋 Google Forms API，進入服務詳細頁後按「啟用 API」。若畫面已顯示「停用 API」或狀態「已啟用」，代表這一步已完成；API 是專案級設定，若在錯的專案啟用，程式仍然會找不到它。

  1. 進入「API 和服務」→「程式庫」。
  2. 搜尋 Google Forms API，開啟名稱完全相同的官方服務。
  3. 若按鈕顯示「啟用」，點擊一次並等待狀態完成；若已啟用，保留現況即可。
  4. 記下你目前仍在正確的 Cloud 專案中，接著再處理 OAuth。

成功判斷

Google Forms API 服務頁面顯示已啟用，且上方專案名稱與步驟 03、04 相同。

06Google Cloud 專案

確認憑證頁

你要做什麼

進入「API 和服務」→「憑證」，把這裡當成之後檢查用戶端的總入口。現在先確認頁面能開啟，不急著建立用戶端。

  • 確認頁面標題為「憑證」，不是 API Library 或配額頁。
  • 找到「建立憑證」按鈕，稍後會從這裡建立 OAuth 用戶端。
  • 若看不到按鈕，檢查帳號權限與目前選取的專案。

注意事項

憑證頁可能列出其他用途的金鑰。不要刪除或下載不屬於這次練習的項目；本手冊只會新增一個桌面版 OAuth 用戶端。

成功判斷

你已能開啟正確的憑證頁，並知道下一段設定會從 Google Auth Platform 開始。

07Google Auth Platform

進入 Google Auth Platform

你要做什麼

Google 目前把 OAuth 同意畫面、品牌、受眾與用戶端整理在 Google Auth Platform。從 Cloud Console 的品牌或 OAuth 總覽入口進入即可。

  1. 確認仍在同一個 Cloud 專案。
  2. 從「API 和服務」或側邊導覽找到 Google Auth Platform。
  3. 若畫面顯示開始設定，按流程進入品牌資料；不要先建立不明用途的用戶端。

成功判斷

你已看到 Google Auth Platform 的導覽，並能找到品牌資料、受眾、資料存取權與用戶端等設定入口。

08Google Auth Platform

建立品牌資料

你要做什麼

品牌資料會出現在授權畫面，讓教師知道是哪個應用程式正在請求權限。名稱要清楚、可辨識，不要放帳號、專案編號或私人資訊。

  • 應用程式名稱使用像「教師 Forms 測試工具」這種用途清楚的名稱。
  • 選擇你能收信的使用者支援聯絡資料。
  • 若需要開發者聯絡資料，使用同一個可管理此專案的聯絡方式。
  • 儲存後回到總覽，確認品牌狀態已完成。

應用程式名稱規則

避免使用容易誤認為 Google 官方服務的名稱，也不要放入私人帳號、學校完整名冊或專案識別值。名稱應描述「這個測試工具做什麼」。

成功判斷

品牌資料頁顯示已儲存，授權畫面將能清楚告訴使用者這是一個教師自己的測試工具。

09Google Auth Platform

選擇外部測試對象

你要做什麼

本機教學工具通常先使用「外部」測試，讓你可以用自己的 Google 帳號試跑 OAuth。外部不等於公開給所有人；測試階段仍由測試使用者名單控管。

  1. 在受眾設定中選擇「外部」，適合個人或研習示範專案。
  2. 如果你的 Workspace 管理員要求只能內部使用，依學校政策選擇「內部」。
  3. 儲存後確認測試狀態仍是測試中，而不是立刻送出公開驗證。

注意事項

測試模式會要求授權帳號先加入測試使用者。看到未驗證應用程式提示時，先確認這是你自己建立的工具，再依畫面流程繼續。

成功判斷

受眾設定已儲存為適合本次教學的測試模式，並且你知道之後要把實際登入帳號加入測試使用者。

10Google Auth Platform

填寫聯絡資訊與同意事項

完成品牌資料的聯絡欄位與必要同意項目。這些資料是讓使用者知道如何聯絡開發者，也是 Google 顯示授權資訊的必要條件。

  • 填入能真正收到問題的使用者支援聯絡資料。
  • 閱讀並勾選必要的服務條款與資料使用同意。
  • 儲存後回到總覽，確認品牌與受眾區塊都沒有待處理警示。

注意事項

不要把測試帳號清單、權杖內容或本機路徑填進品牌說明；這裡只需要公開給授權使用者看的聯絡與應用程式資訊。

成功判斷

所有必要欄位都已儲存，總覽不再要求補填聯絡資訊或同意事項。

12OAuth 用戶端與 API

確認 OAuth 總覽

你要做什麼

回到 Google Auth Platform 的 OAuth 總覽，確認品牌、受眾與資料存取權已經有狀態。這個總覽是建立用戶端前的檢查站。

  • 品牌資料顯示完成或已儲存。
  • 受眾設定符合目前的測試方式。
  • 資料存取權至少會包含 Google Forms API 需要的 scopes。
  • 找到建立或管理用戶端的入口。

Forms API / Scopes

成功判斷

13OAuth 用戶端與 API

建立 OAuth 桌面版用戶端

你要做什麼

本機 Python 會在你的電腦上開啟瀏覽器完成授權，因此用戶端類型要選「桌面應用程式」。不要選 Web application，也不要自行填入不存在的 callback 網域。

  1. 在用戶端區塊選擇「建立用戶端」。
  2. 應用程式類型選擇「桌面應用程式」。
  3. 名稱使用 teacher-forms-desktop 這類不含個資的識別名稱。
  4. 建立完成後，不要把用戶端設定畫面內容貼到公開地方。

localhost callback

桌面流程會使用本機 callback。若授權後回不到程式，先確認瀏覽器與 Python 仍在同一台電腦，並讓授權流程自行選可用的本機連接埠。

成功判斷

用戶端清單中出現一個類型為「桌面應用程式」的新項目，且名稱能辨識本次研習用途。

17本機授權與成果驗證

執行本機授權並取得 token.json

你要做什麼

把 credentials.json 放在專案資料夾，建立 authorize.py，再從同一個資料夾執行。程式只會開啟瀏覽器讓你登入與同意；本手冊不會替你執行 OAuth。

authorize.py

只使用 placeholder 與必要 scopes 的安全範例

from pathlib import Path
import json

from google_auth_oauthlib.flow import InstalledAppFlow

CREDENTIALS_PATH = Path("credentials.json")
TOKEN_PATH = Path("token.json")
SCOPES = [
    "https://www.googleapis.com/auth/forms.body",
    "https://www.googleapis.com/auth/drive.file",
]

client_config = json.loads(CREDENTIALS_PATH.read_text(encoding="utf-8"))
flow = InstalledAppFlow.from_client_config(client_config, SCOPES)
credentials = flow.run_local_server(port=0)
TOKEN_PATH.write_text(credentials.to_json(), encoding="utf-8")
print("授權完成：token.json 已寫入目前專案資料夾。")

  1. 在專案資料夾安裝必要套件：google-auth-oauthlib。
  2. 將上方片段存成 authorize.py，在同一資料夾執行。
  3. 瀏覽器出現授權畫面時，登入已加入測試使用者的帳號。
  4. 同意後回到終端機，確認專案資料夾新增 token.json。

檔案位置與 localhost callback

找不到 credentials.json 或 token.json 時，先用檔案總管確認目前資料夾；授權頁回不來時，確認本機瀏覽器沒有阻擋 localhost，並重新執行一次流程。

成功判斷

你已在瀏覽器完成使用者授權，終端機顯示完成訊息，且 token.json 只存在自己的專案資料夾。

18本機授權與成果驗證

建立並驗證測試表單

你要做什麼

使用剛取得的 token.json 建立一份不含真實學生資料的測試表單，接著用瀏覽器開啟回傳的表單連結，確認成果真的存在。

create_test_form.py

使用現有 token 建立無個資的測試表單

from pathlib import Path

from google.oauth2.credentials import Credentials
from googleapiclient.discovery import build

TOKEN_PATH = Path("token.json")
SCOPES = [
    "https://www.googleapis.com/auth/forms.body",
    "https://www.googleapis.com/auth/drive.file",
]

credentials = Credentials.from_authorized_user_file(
    str(TOKEN_PATH), SCOPES
)
forms_service = build("forms", "v1", credentials=credentials)
result = forms_service.forms().create(
    body={"info": {"title": "教師 OAuth 測試表單"}}
).execute()
print("測試表單已建立，請使用回傳的表單連結在瀏覽器驗證。")
print(result.get("responderUri", "表單連結尚未回傳。"))

  1. 將片段存成 create_test_form.py，在同一專案資料夾執行。
  2. 確認終端機回傳測試表單連結，不要把連結或識別值貼到公開地方。
